# Централизованная балансировка нагрузки (лабораторная)

Система балансировки для распределённой обработки «запросов» (задачи в духе университетского API: зачётка, расписание, новости) с топологией **дерево** и **волновым алгоритмом** сбора нагрузки.

## Схема сети (дерево)

```
         [Master :9000]
        /       |      \
   W1:8001   W2:8002   W3:8003
```

- **Master** — центральный узел: знает дерево, раз в 5 сек собирает нагрузку с воркеров (волна) и отдаёт команды на перераспределение.
- **Workers** — узлы-исполнители: хранят очередь «задач», отдают нагрузку по запросу, принимают/отправляют задачи по команде Master.

## Что реализовано

1. **Оценка загрузки** — каждый воркер считает нагрузку как `len(tasks)`.
2. **Волновой алгоритм** — Master опрашивает всех детей (GET /load), получает карту нагрузок.
3. **Принятие решения** — если разница max−min ≥ 2, Master даёт команду перекинуть часть задач с перегруженного на наименее загруженный.
4. **Перемещение** — Master вызывает POST /transfer на перегруженном воркере (target_url + count); воркер отправляет задачи на другой воркер (POST /tasks/accept).

## Запуск демо (3 воркера + 1 мастер)

Из корня проекта `back_uni/`:

```bash
# 1) Запустить три воркера (в трёх терминалах или в фоне)
WORKER_NODE_ID=worker_8001 python3 -m uvicorn balancer.worker:app --host 0.0.0.0 --port 8001
WORKER_NODE_ID=worker_8002 python3 -m uvicorn balancer.worker:app --host 0.0.0.0 --port 8002
WORKER_NODE_ID=worker_8003 python3 -m uvicorn balancer.worker:app --host 0.0.0.0 --port 8003

# 2) В другом терминале — мастер (порт 9000)
python -m uvicorn balancer.master:app --host 0.0.0.0 --port 9000
```

Или одной командой воркеры в фоне (Bash):

```bash
chmod +x balancer/run_workers.sh
./balancer/run_workers.sh
# затем вручную: python -m uvicorn balancer.master:app --host 0.0.0.0 --port 9000
```

## Централизация (как в примере с клиникой)

| Клиника | Твой проект |
|--------|-------------|
| `POST /register_patient` (порт 5000) | `POST http://127.0.0.1:9000/register_request` |
| Сервер сам выбирает врача/филиал и записывает пациента | Мастер сам выбирает наименее загруженный воркер и перенаправляет туда запрос |
| `GET /balance` (порт 5001) — ручная балансировка | `GET http://127.0.0.1:9000/balance` — ручной шаг балансировки |

**Клиент (студент):** один запрос к мастеру — как в клинике один запрос на регистрацию.

```bash
python3 balancer/client.py
# Ввести тип запроса: gradebook / schedule / news
```

Или через curl:
```bash
curl -X POST http://127.0.0.1:9000/register_request -H "Content-Type: application/json" -d '{"request_type":"gradebook"}'
```

## Демонстрация перераспределения

1. **Нагрузить один воркер** (например 8001):

```bash
# Отправить 10 «запросов» на воркер 8001
for i in $(seq 1 10); do
  curl -X POST http://127.0.0.1:8001/tasks -H "Content-Type: application/json" -d '{"type":"gradebook"}'
done
```

2. **Подождать цикл балансировки** (до 5 сек). Master увидит нагрузки (10, 0, 0), отдаст команду перекинуть часть с 8001 на 8002 и 8003.

3. **Проверить нагрузки:**

```bash
curl http://127.0.0.1:9000/loads 
curl http://127.0.0.1:8001/load
curl http://127.0.0.1:8002/load
curl http://127.0.0.1:8003/load
```

### Что значит вывод `/loads`

- В ответе должны быть **три** ключа: `worker_8001`, `worker_8002`, `worker_8003`. Если ключа нет или значение **-1** — этот воркер не запущен или не отвечает (запустите все три воркера).
- Числа — это количество задач на каждом узле. После перераспределения они выравниваются (например 3, 4, 3 вместо 10, 0, 0).

### Пошагово: что делать для демо

1. Запустить **три** воркера (три терминала или скрипт `run_workers.sh`).
2. Запустить мастер: `python -m uvicorn balancer.master:app --host 0.0.0.0 --port 9000`.
3. Проверить: `curl http://127.0.0.1:9000/loads` — должно быть что-то вроде `{"worker_8001":0,"worker_8002":0,"worker_8003":0}` (или -1 только у недоступных).
4. Нагрузить один воркер: `python3 balancer/flood_one.py 8001 10`.
5. Подождать **5–10 секунд** (цикл балансировки).
6. Снова: `curl http://127.0.0.1:9000/loads` — нагрузки должны выровняться (например 3, 4, 3 или 4, 3, 3).

## API для отчёта и мониторинга (Flutter)

- **GET http://127.0.0.1:9000/tree** — структура дерева и текущие нагрузки (для визуализации).
- **GET http://127.0.0.1:9000/loads** — только словарь `node_id → load`.
- **GET http://127.0.0.1:8001/tasks** (и 8002, 8003) — список задач на воркере.

Во Flutter можно показывать дерево узлов, раскрашивать по нагрузке (зелёный/красный) и обновлять данные по таймеру из `/tree` или `/loads`.

## Визуализация в виде таблицы (HTML)

Для создания HTML-файла с таблицей нагрузок:

```bash
# Из корня проекта back_uni/
python3 balancer/visualize_table.py до    # создать файл "до балансировки"
python3 balancer/visualize_table.py после # создать файл "после балансировки"
```

Или автоматически создать оба файла:

```bash
chmod +x balancer/create_visualization.sh
./balancer/create_visualization.sh
```

Файлы сохраняются в `balancer/balancer_visualization_до_балансировки.html` и `balancer_visualization_после_балансировки.html`. Откройте их в браузере для просмотра красивой таблицы с деревом узлов, нагрузками и статистикой.

## Файлы

| Файл | Назначение |
|------|------------|
| `config.py` | Порты и дерево узлов (TREE). |
| `models.py` | Модель задачи (id, type, created_at). |
| `worker.py` | Узел-воркер: очередь задач, /load, /tasks, /tasks/accept, /transfer, /echo_token. |
| `group.py` | Промежуточный узел (Group): /echo_token для алгоритма "Эхо". |
| `echo_algorithm.py` | Реализация алгоритма "Эхо" для сбора нагрузок. |
| `master.py` | Центр: алгоритм "Эхо", решение о перераспределении, /visualize, /register_request. |
| `visualize_table.py` | Генерация HTML-таблицы с визуализацией дерева и нагрузок. |
