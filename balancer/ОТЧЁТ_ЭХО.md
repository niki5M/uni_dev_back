# Отчёт: Алгоритм "Эхо" для централизованной балансировки нагрузки

**Тема:** Распределённая обработка запросов университетского приложения (зачётка, расписание, новости).  
**Алгоритм:** Централизованный с использованием волнового алгоритма "Эхо".  
**Топология:** Ориентированное дерево (Master → Groups → Workers).

---

## 1. Схема сети (топология дерева)

```
                    [Master :9000] (инициатор)
                   /      |      \
        [Group_A:9001] [Group_B:9002] [Group_C:9003] (промежуточные узлы)
         /    |          /    |          /    |
    [W1:8001][W2:8002] [W3:8003][W4:8004] [W5:8005][W6:8006] (листья)
```

**Структура:** Master (инициатор) → 3 промежуточных узла (группы) → 6 воркеров (листья).

**Файл:** `balancer/config.py` — структура `TREE` с полями `parent`, `children`, `port`, `type`.

---

## 2. Реализация алгоритма "Эхо"

### 2.1 Процесс для инициатора (Master)

**Код:** `balancer/master.py` → функция `run_wave_and_rebalance()` вызывает `echo_algorithm_collect_load()`.

**Алгоритм:**
1. Отправить маркер всем соседям: `for u in Out(this) do out token to u`
2. Ждать эхо от всех соседей: `while counter < card(Out(this)) do receive token`
3. Получить все данные о нагрузке, вернуть OK

**Реализация:** `balancer/echo_algorithm.py` → `echo_algorithm_collect_load("master")`:
- Отправляет POST `/echo_token` всем детям (group_A, group_B, group_C)
- Собирает ответы с данными о нагрузке всех воркеров

### 2.2 Процесс для не-инициаторов (Groups и Workers)

**Код:** 
- Промежуточные узлы: `balancer/group.py` → эндпоинт `/echo_token`
- Листья: `balancer/worker.py` → эндпоинт `/echo_token`

**Алгоритм:**
1. Получить маркер от `u`, запомнить `pre(this) = u`
2. Отправить маркер всем соседям кроме `pre(this)`: `for (u in Out(this))&(u ≠ pre(this)) do out token to u`
3. Ждать эхо от всех детей: `while counter < card(Out(this)) do receive token`
4. Вернуть эхо родителю `pre(this)` с данными о нагрузке

**Реализация:**
- **Group:** получает маркер от Master, отправляет детям-воркерам, собирает их эхо, возвращает Master
- **Worker (лист):** получает маркер от Group, возвращает эхо со своей нагрузкой (`len(tasks)`)

## 3. Визуализация до и после балансировки

### 3.1 Эндпоинт визуализации

**GET http://127.0.0.1:9000/visualize**

Возвращает:
- Текстовое дерево с нагрузками на каждом узле
- Словарь всех нагрузок
- Словарь только воркеров

**Пример ответа:**
```json
{
  "tree": "master (инициатор)\n├── group_A (нагрузка: 0)\n│   ├── worker_8001 (нагрузка: 10)\n│   └── worker_8002 (нагрузка: 0)\n...",
  "loads": {"group_A": 0, "worker_8001": 10, "worker_8002": 0, ...},
  "workers_only": {"worker_8001": 10, "worker_8002": 0, ...}
}
```

### 3.2 Демонстрация для отчёта

**Шаг 1: Запустить все узлы**

```bash
# Запустить группы и воркеры (скрипт или вручную)
chmod +x balancer/start_all.sh
./balancer/start_all.sh

# Запустить мастера
python -m uvicorn balancer.master:app --host 0.0.0.0 --port 9000
```

**Шаг 2: Нагрузить один воркер (ДО балансировки)**

```bash
# Отправить 10 задач на worker_8001
python3 balancer/flood_one.py 8001 10

# Визуализация ДО балансировки
curl http://127.0.0.1:9000/visualize
```

**Шаг 3: Запустить балансировку**

```bash
# Ручной запуск (или подождать автоматический цикл ~5 сек)
curl http://127.0.0.1:9000/balance
```

**Шаг 4: Визуализация ПОСЛЕ балансировки**

```bash
curl http://127.0.0.1:9000/visualize
curl http://127.0.0.1:9000/loads
```

**Результат:** Нагрузки выровнялись (например, было 10/0/0, стало 3/4/3).

## 5. Что описать в отчёте

### 5.1 Оценка загрузки
Каждый воркер считает нагрузку как `len(tasks)`. При получении маркера возвращает эхо с этой нагрузкой.

### 5.2 Инициация (алгоритм "Эхо")
Инициатор (Master) отправляет маркер всем соседям (Groups). Каждый узел:
- Получает маркер от родителя (`pre(this)`)
- Отправляет маркер всем детям (кроме родителя)
- Листья возвращают эхо с нагрузкой
- Промежуточные узлы собирают эхо от детей и передают родителю
- Инициатор получает эхо от всех соседей и знает нагрузки всех узлов

**Код:** `balancer/echo_algorithm.py`, `balancer/group.py`, `balancer/worker.py`

### 5.3 Принятие решения
Центральный узел (Master) сравнивает нагрузки всех воркеров. Если разница max−min ≥ 2, решает перекинуть часть задач с перегруженного на наименее загруженный.

**Код:** `balancer/master.py` → `run_wave_and_rebalance()`

### 5.4 Перемещение
Master отправляет команду перегруженному воркеру: `POST /transfer` с `{"target_url": "...", "count": N}`. Воркер отправляет N задач на целевой воркер через `POST /tasks/accept`.

**Код:** `balancer/worker.py` → `/transfer`, `/tasks/accept`
